1. EXECUTIVE SUMMARY
================================================================================
This report provides a complete, code-level technical analysis of the Firebase
Functions backend for the "white_label_app_non_subscription" project.

The backend is currently written using Cloud Functions for Firebase v2 (Cloud
Functions Gen 2 / Cloud Run based) running on Node.js 22 with CommonJS modules
located across functions/index.js, functions/src/createPaymentSession.js,
functions/src/iciciPaymentFunctions.js, functions/src/icici_service.js, and
functions/src/icici_hash.js.

Core Business Capabilities:
1. ICICI Payment Gateway Integrations (Live Unified Payment Gateway supporting
   Cards, NetBanking, and UPI dynamic QR code generation, webhook callback
   processing, status verification, automated reconciliation, and admin refunds).
2. Multi-Tenant FCM Push and In-App Notifications (Ticket creation alerts,
   engineer assignment notifications, ticket status updates, and expiry notices).
3. Transactional Email Engine with Automated Exponential Backoff Retries
   (SMTP delivery via Hostinger using nodemailer backed by a Firestore mail queue).
4. Subscription Lifecycle & Expiry Notification Engines (Automated daily cron
   schedulers evaluating multi-tenant subscriptions across collection groups with
   3-day, 2-day, and 1-day warnings, plus monthly status reports).
5. Real-time Payment Activity Auditing & Invoice PDF Generation (Dynamic vector
   PDF invoice rendering using pdfkit and automated email dispatch).
6. Authentication & Password Recovery Utilities (Direct HTTP endpoints handling
   OTP generation, storage, email dispatch, and Firebase Auth password resets).

Source Code Inventory Summary:
- Active Exported Functions in functions/index.js: 17 functions
- Additional Internal / Unexported Functions in functions/src/: 2 functions
- Reference / Template Functions in functions/INDEX_JS_REFERENCE.js: 9 functions
- Total Active/Internal Functions Analyzed in Source: 19 functions

All active functions are fully convertible to Firebase Functions v1 (Cloud
Functions Gen 1). Special attention must be paid to Google Cloud Serverless
VPC Access Connectors (icici-connector with egress ALL_TRAFFIC) used to route
outbound traffic through a static whitelisted NAT IP for ICICI Bank API
compliance.

4. DETAILED FUNCTION ANALYSIS
================================================================================

4.1 Payment & Transaction Functions:

A. createPaymentSession (functions/src/createPaymentSession.js:20)
- Trigger: onRequest (v2/https)
- Flow: HTTP POST -> Validate parameters -> Generate unique 20-char txnId ->
  Create /payments/{txnId} doc (status: PENDING) -> Call ICICI initiateSale or
  generateUpiQr via VPC Connector -> Update /payments/{txnId} with redirectUrl /
  upiQR -> Return JSON response.
- VPC: icici-connector (egress: ALL_TRAFFIC).
- DB Operations: Write to /payments/{txnId}.

B. paymentCallback (functions/src/iciciPaymentFunctions.js:83)
- Trigger: onRequest (v2/https)
- Flow: Bank Webhook (POST) / Browser Redirect (GET) -> If GET: Update status &
  render HTML closing page -> If POST: Run Firestore transaction on
  /payments/{txnId} -> Verify idempotency -> Verify amount integrity -> Call
  ICICI statusCheck API directly -> Map status -> Update /payments/{txnId} ->
  If SUCCESS: Mirror to /{tenantId}/{appId}/payment_transactions/{txnId}.
- DB Operations: Read/Write /payments/{txnId}, Write to payment_transactions.

C. verifyPayment (functions/src/iciciPaymentFunctions.js:279)
- Trigger: onRequest (v2/https)
- Flow: HTTP POST with txnId -> Query ICICI Bank statusCheck API via VPC ->
  Update /payments/{txnId} -> If SUCCESS: Mirror to payment_transactions ->
  Return status JSON.
- DB Operations: Read/Update /payments/{txnId}, Write to payment_transactions.

D. processPaymentSuccess (functions/index.js:464)
- Trigger: onDocumentWritten("{tenantId}/{appId}/payment_transactions/{txnId}")
- Flow: Trigger on status=="SUCCESS" -> Fetch user email from tenant users doc
  (or Auth) -> Calculate 18% GST -> Calculate expiry -> Generate PDF receipt
  using pdfkit -> Add email document to /mail collection -> Update transaction
  doc with invoiceNo -> Update /{tenantId}/{tenantId}/subscription/{uid}.
- DB Operations: Read users, Write /mail, Update payment_transactions, Write
  subscription.

E. logPaymentActivity (functions/index.js:897)
- Trigger: onDocumentWritten("payments/{txnId}")
- Flow: Listen to payments collection -> Skip if PENDING -> If SUCCESS or FAILED:
  Mirror audit document into /{tenantId}/{appId}/payment_logs/{txnId}.
- DB Operations: Write /{tenantId}/{appId}/payment_logs/{txnId}.

F. adminProcessRefund & processRefund (functions/src/iciciPaymentFunctions.js)
- adminProcessRefund Trigger: onCall (v2/https)
- processRefund Trigger: onRequest (v2/https)
- Flow: Authenticate admin -> Validate refundable balance -> Execute ICICI
  refund API via VPC -> Update /payments/{orderId} status to REFUNDED or
  PARTIAL_REFUND -> Write audit records to /refunds and /refund_logs.


4.2 Notification & Ticketing Functions:

A. handleTicketCreation (functions/index.js:153)
- Trigger: onDocumentCreated("{tenantId}/{appId}/Admin_details/{bookingId}")
- Flow: Read ticket -> Query admin tokens at
  /{tenantId}/{appId}/notifications_tokens/admin/tokens -> Send FCM high-priority
  push -> Add in-app notification doc to /{tenantId}/{appId}/notifications.

B. handleTicketStatusUpdate (functions/index.js:232)
- Trigger: onDocumentUpdated("{tenantId}/{appId}/Admin_details/{bookingId}")
- Flow: If assignedEmployee changed: Send push to Engineer & Customer -> If
  ticket status changed: Send push to Customer -> If engineerStatus changed:
  Notify Admins -> Add in-app notification doc to notifications collection.

C. testNotify (functions/index.js:129)
- Trigger: onRequest (v2/https)
- Flow: Fetch token for specific role/user -> Send test FCM message.


4.3 Email Queue & Schedulers:

A. processMailDocument (functions/index.js:371)
- Trigger: onDocumentWritten("mail/{docId}")
- Flow: Check status.state=="PENDING" -> Configure Nodemailer SMTP transporter
  (Hostinger) -> Send email with base64 PDF attachments -> On success: Set state
  to "SENT" -> On failure: Calculate exponential backoff (2^attempts * 60s)
  and set state to "RETRY" or "ERROR".

B. scheduledEmailRetry (functions/index.js:440)
- Trigger: onSchedule("*/30 * * * *") (Every 30 minutes)
- Flow: Query mail where status.state=="RETRY" and nextRetryAt <= now -> Reset
  status.state to "PENDING" (re-triggering processMailDocument).

C. checkSubscriptionExpiryReminders (functions/index.js:1330)
- Trigger: onSchedule("0 9 * * *", timeZone: "Asia/Kolkata") (Daily at 09:00 AM IST)
- Flow: Query collectionGroup("subscription").where("status", "==", "active") ->
  For 3, 2, or 1 days remaining: Queue email in /mail, dispatch FCM alert to
  Admin, create in-app notification, and mark reminderSent flag -> For 6-month
  or yearly plans: Dispatch monthly check-in reminder on monthly anniversary.

D. scheduledSubscriptionReminders (functions/index.js:954)
- Trigger: onSchedule("0 3 * * *") (Daily at 03:00 UTC)
- Flow: Scans collectionGroup("subscription") for 2-day and 1-day reminders;
  queues reminder emails.

E. reconcileStuckPayments (functions/index.js:1591)
- Trigger: onSchedule("0 * * * *", timeZone: "Asia/Kolkata") (Hourly)
- Flow: Query payments where status=="PENDING" created >= 30m ago -> Query
  ICICI statusCheck API -> Update status to SUCCESS or FAILED.

F. sendOTP & verifyOTPAndResetPassword (functions/index.js:1191 & 1260)
- Trigger: onRequest (v2/https)
- Flow:
  - sendOTP: Generates 6-digit OTP, saves in /otps/{email} (10m expiry), sends
    email via Nodemailer.
  - verifyOTPAndResetPassword: Validates OTP against /otps/{email}, updates
    password in Firebase Auth and legacy admin doc, deletes OTP record.

7. v2 -> v1 COMPATIBILITY ANALYSIS
================================================================================
Key Code Differences:
1. Handler Signatures:
   - v2 Firestore: (event) where data is event.data and params is event.params.
   - v1 Firestore: (snap, context) or (change, context) where data is snap.data()
     or change.before/after.data(), and params is context.params.
   - v2 Callable: (request) where payload is request.data and auth is request.auth.
   - v1 Callable: (data, context) where payload is data and auth is context.auth.
   - v2 Scheduler: onSchedule(options, (event) => ...)
   - v1 Scheduler: functions.pubsub.schedule(cron).timeZone(tz).onRun((context) => ...)

2. Options Configuration:
   - v2: Passed as first argument object { region, vpcConnector, memory: "256MiB", timeoutSeconds: 60 }
   - v1: Chained via functions.runWith({ vpcConnector, memory: "256MB", timeoutSeconds: 60 }).region("us-central1")
   - Memory format: "256MiB" (v2) -> "256MB" (v1).
   - "invoker: public" is omitted in v1 (Cloud Functions Gen 1 is public by default).

11. SECURITY AND RELIABILITY REVIEW
================================================================================
Confirmed Source Observations:
1. Trapped Functions Bug in iciciPaymentFunctions.js:
   reconcilePayments and activateSubscription are defined inside verifyPayment's
   callback body. They are not initialized on cold start and are never exported
   in index.js.
2. Dual Expiry Schedulers:
   Both scheduledSubscriptionReminders and checkSubscriptionExpiryReminders are
   active. checkSubscriptionExpiryReminders is the newer version.
3. VPC Connector Dependency:
   VPC connector settings must be preserved in v1 via runWith({ vpcConnector: "icici-connector", vpcConnectorEgressSettings: "ALL_TRAFFIC" }).

15. MIGRATION RISKS AND CONSIDERATIONS
================================================================================
1. VPC Egress: Omitting runWith({ vpcConnector: "icici-connector", vpcConnectorEgressSettings: "ALL_TRAFFIC" })
   will route traffic through dynamic GCP IPs and cause ICICI Bank API rejections.
2. Parameter Mapping: In v2 params are on event.params; in v1 they are on context.params.
3. Data Snapshots: In v2 onCreate is event.data.data(); in v1 it is snap.data().
